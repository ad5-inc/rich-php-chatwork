# 0007 メッセージは例外の種類で分ける

- 状態: 採用

## 背景

元の文言を正規表現で伏せる形を何度か見直したが、どんな文字でも来うる文言に対して「これで全部」とは言えなかった。とくに DB の例外は、値を埋めた SQL と接続先（Host・Port・Database）を文言に含む。

## 選んだ物

- **形の分かる例外**（`QueryException`・`RequestException`・`ConnectionException`）は、部品が安全な部品だけで文言を組み立て直す。元の文言は使わない
  - DB のドライバーの文言は**許可リスト**の形に当たったときだけ、値を伏せて出す。当たらなければ番号だけ
  - 接続の失敗はドライバーの文言を使わず、固定の言葉にする
  - HTTP のパスは段ごとの許可リスト
- **それ以外**は、送る設定のときだけ元の文言を規則で伏せる
- 組み立て・伏せる処理に失敗したら、元の文言には戻さず、項目ごと省く
- 件名には文言を入れず、値を含まない要約だけを出す

規則と表は [redaction.md](../redaction.md)、本文の形は [message-format.md](../message-format.md)。

## 選ばなかった物

| 案 | 選ばなかった理由 |
| --- | --- |
| すべての文言を伏せる規則だけで守る | 規則の取りこぼしが残り続ける |
| 許可リストの代わりに、伏せる所の一覧（拒否リスト）を持つ | 知らない形の文言がそのまま出る |

## 代償

- 許可リストに無い DB の文言は番号だけになる（権限の不足など）。中身はログで見る
- Laravel やドライバーの版で文言の形が変わると、その形が出なくなる（値は出ない）
- 伏せる規則は伏せなくてよい物も伏せることがある（`session_lifetime: 120`・12 桁の内部 ID など）
